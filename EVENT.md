## Submission

Submit on [Alkemio](https://alkem.io/onegov-hackathon) before **Thursday 10 December, 14:00**. A submission contains:

- A link to your **public GitHub repository** (a fork of the starter repository or your own), with an open source licence and a README that says how to run your work.
- A short explanation of your approach, assumptions and limitations, including what is simulated.
- Your pitch deck (max. 10 slides). The pitch itself is max. 3 minutes.

Each challenge adds its own deliverables: see CHALLENGE.md in the challenge's repository. A Pull Request into a starter repository is welcome, but optional: the Alkemio entry is your submission.

## How judging works

1. **Must criteria are pass or fail.** A submission that misses a Must is not valid. Should and Could criteria set the strong submissions apart. Each challenge lists its criteria in `docs/judging-criteria.md`.
2. **First round, per challenge (14:00-15:00).** Every team pitches for its challenge's jury and challenge owners. At 15:00 they select the best team per challenge.
3. **Technical jury (14:00-15:00).** Reviews every submission in Alkemio and writes feedback there: is the repository public with an open source licence, is the code readable with a clear README, can someone else reproduce it, are assumptions documented and is it clear what is simulated. This score counts alongside the first round.
4. **Final (15:45).** The four finalists pitch to the grand jury, who score each team from 1 (weak) to 5 (excellent) on six criteria, 30 points in total:

| Criterion | Question |
|---|---|
| Impact | Does it solve the question structurally? |
| Feasibility | Is it realistic to implement within a government organisation? |
| Digital autonomy | Does it give more control over own data, systems or infrastructure? |
| Open source potential | Can others reuse and develop it further? |
| Fit with the challenge | Does it answer the question asked? |
| Presentation | Is it clear and convincing for a broad audience? |
